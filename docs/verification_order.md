## 开始前的共同条件

1. 固定目标：当前兼容性候选是 GCC 小端布局、32 位 unsigned int，QCP 使用 ILP32/little endian。完成原位域与 packed_fields 的表示关系和读写对应证明后，才能把适配版本的证明结论迁回原实现。原生 x64 对比测试不是该证明。
2. 建立可复用谓词：输入字节数组、parser 状态、token 单元、token 数组已用前缀与剩余容量、token 对应子串、深度优先 token 树及其唯一末尾标记。允许解析中间状态与完整输出使用不同谓词。
3. 输入位置通常满足 0 <= str_pos <= str_len；容量与已用数量满足 0 <= token_count <= max_tokens。具体函数可以要求更强或更弱的条件，不能把统一谓词写成不必要的限制。
4. 给 strlen、memset、日志固定参数接口建立与真实目标一致的契约，处理 sizeof 乘法和指针差的范围。诊断用占位头不能用于正式证明。
5. 分开规定成功、格式错误、不完整、容量不足等返回路径。错误返回后不能假定输入位置、深度或部分 token 被回滚。
6. 函数没有循环时无需添加循环不变量；有循环时才补。递归函数组先联合制定规约，再分别证明函数体，终止性另给下降度量。

## 单函数完成标准

- 明确输入域、内存所有权、可修改区域与成功/失败后置条件。
- 必要时给循环不变量或递归度量；不把尚未证明的强性质当作假设塞进调用方。
- 生成并关闭该函数的全部相关证明义务，记录所用外部契约。
- 检查调用方能建立这些前置条件；共享谓词或规约改变后复查受影响的调用方。
- 依据现有 QCP 工作流检查手工证明与 goal_check；自动生成文件中的占位项按项目既定机制处理，不能把整文件只有前端退出码 0 当作证明完成。
